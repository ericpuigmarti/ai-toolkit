# Product context — blank template

This file is blank on purpose. Copy it into this same `references/` folder, rename it to match a real product (e.g. `acme-product-context.md`), and fill in every field with your own role, team, company, and product details. Delete sections that do not apply. Keep the filled-in version out of any repo you don't fully control — it will contain real, possibly confidential, organizational detail.

Read a filled-in version of this file only when critiquing work for the product it describes. For any other product, use context supplied by the user and do not apply these rules.

## Review emphasis

For this product, add `Brand and product fit` to the critique when there is enough evidence to assess it.

For _[sensitive-audience]_-facing screens, give additional weight to:

- Clear, reassuring, and actionable content
- Unambiguous next steps and system status
- Low cognitive burden
- Error prevention and recovery
- Readability and visible accessibility risks
- Appropriate trust signals without overstating outcomes

For component or design-system work, give additional weight to:

- Component selection and composition
- Token and spacing consistency
- Variant and state coverage
- Reuse across relevant product surfaces

## Required source material

This file should not contain the product's complete brand principles, copy standards, or design-system specifications — link to those instead of pasting them in. When those materials are available, read them before making compliance claims. Ground every brand, copy, or component-system issue in the supplied source and cite the rule by name when useful.

If the source material is unavailable:

- Assess universal design quality normally.
- Phrase product-specific observations as questions or risks, not violations.
